Database schema

Everything agents do ends up in a database. Know its tables and you can analyse a simulation with plain SQL, pandas or ySights.

Where it is

One database per experiment: y_web/experiments/<experiment>/database_server.db (SQLite). HPC runtimes use the same table names, but some of their tables identify rows with a UUID (text) instead of an auto-incrementing integer id: check the column type before joining across tables.

Time

Time is the table rounds (one row per slot, with day and hour). Other tables point to it with round.

The tables

Forum and microblogging share the schema. Pick a table to see its columns and how it links to the others, or search by name or column. Some columns appear only where they apply, such as agent_opinion.stubborn or the image fields of the forum.

Photo sharing starts from the same ideas but identifies every row with a UUID (text) instead of an integer, and models photos, comments, stories and messages. Tables marked new or changed differ from microblogging; new columns of shared tables are flagged inside the table.

Replaced tables

Microblogging and forumPhoto sharing

post (comments)comments
post_hashtags, post_topicsphoto_hashtags, photo_topics

reactions.type (like or dislike)reactions.reaction_type (six emoji reactions) and emotion_id
recommendations.post_idsrecommendations.photo_ids

In post_sentiment, post_toxicity and post_emotions the column post_id refers to a photo or to a comment. Photo sharing has no news or forum-image tables, no voting, and only two memory tables. Absent: agent_custom_features, article_topics, articles, image_posts, images, memory_community_digests, memory_items, memory_thread_cards, reply_inbox_state, simulation_client, sys_messages, voting, websites.
